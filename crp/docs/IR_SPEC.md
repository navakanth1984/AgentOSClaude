# Intermediate Representation Specification (v1.0.0)

This document defines the schema, grammar, constraints, and compilation rules for the Cognitive Runtime Platform (CRP) Intermediate Representation (IR). 

All hypothesis generators must output raw IR matching this specification. The Gate 2 compiler will validate and compile this IR into audited Python templates for execution inside isolated Gate 1 subprocesses.

---

## 1. Design Invariants

1. **Declarative Over Imperative**: IR describes *what* optimization to apply, *its parameters*, and the *objectives*, never *how* to execute it imperatively. Arbitrary code is banned.
2. **Schema-Enforced Versioning**: Every IR document must declare its exact schema version (`1.0.0`) and compiler ABI compatibility class (`1`).
3. **Audited Template Substrate**: The compiler maps IR parameters to pre-audited code templates. Templates have unique IDs, versions, and ABIs. Template IDs are immutable forever: a template ID may be deprecated but its implementation/meaning can never change.
4. **Compiler Never Executes**: The compiler only validates, canonicalizes, and emits source and manifests. It never imports, instantiates, or executes generated plugins. All execution occurs inside Gate 1 sandbox processes.
5. **Compiler Purity**: The compiler is a pure function. Its output must depend only on the input IR, Compiler ABI, and Template Set. It must never depend on the CPU, GPU, OS, environment variables, hostname, locale, timezone, network, randomness, or process ID.
   - **Allowed API List**: The compiler pipeline SHALL only import and invoke modules explicitly listed in the following allow-list: `json`, `hashlib`, `ast`, `typing`, `dataclasses`, `types`. All other modules are strictly forbidden.
   - **Observable Behavior**: Compiler purity is observable from the caller's perspective. Repeated invocations with identical canonical input SHALL produce identical return values and SHALL leave no externally observable state changes except returning artifacts to the caller.
6. **Template Determinism Principle**: For any `(canonical IR, compiler ABI, template version)`, the generated `plugin.py` and `manifest.json` SHALL be byte-identical across all supported platforms, environments, locales, timezones, and executions. Any change that alters generated bytes constitutes a compiler compatibility event requiring an ABI version increment.

## 2. Compiler Trust Boundary & Interface

```
       [ UNTRUSTED ]
   Hypothesis Generators
   External JSON inputs
   Extensions / Metadata
         │
         ▼
 ─────────────────────
   Trusted Compiler      ◄── (IR Schema + Audited Templates + AST Guard)
 ─────────────────────
         │
         ├──────────────────────┐
         ▼                      ▼
     plugin.py            manifest.json
         │                      │
         └──────────┬───────────┘
                    ▼
 ─────────────────────
   Gate 1 Sandbox        ◄── Isolated Subprocess Evaluation (Executes plugin)
 ─────────────────────
```

- **Trusted Components**: IR Schema, Audited Templates, and AST Guard.
- **Untrusted Components**: Hypothesis Generators, External JSON payloads, metadata objects, and extension dictionaries.
- **Interface Boundary**: Only `CompilerArtifact` crosses the package boundary. All intermediate representation forms are kept strictly package-private.
- **Extension Semantics**: The compiler MUST ignore unknown extensions. They SHALL be preserved byte-for-byte through canonicalization, but they SHALL NOT:
  - influence semantic validation,
  - alter template selection,
  - alter compiler outputs,
  - affect generated plugin behavior,
  - or participate in any compiler hashes other than the raw `ir_hash`.

```json
  "ir_abi": 1,
  "name": "BlockQuantizedInt8_v1",

    "block_size": 32,
    "quantization_bits": 8,
    "symmetric": false

    "primary": "memory",
    "secondary": "latency",
    "constraints": {
      "max_accuracy_loss": 0.05,
      "max_latency_ms": 5.0

  },
  "extensions": {},
  "metadata": {}
}
```

## 4. Supported Strategies & Semantic Constraints

### 4.1. `quantization.uniform.v1` (`TEMPLATE-001`)
Global scale and zero-point mapping over entire tensor arrays.
- **Parameters**:
  - `quantization_bits`: `integer` in `[4, 8]`
  - `symmetric`: `boolean`
- **Semantic Rule**: `quantization_bits` must be exactly `8` in `v1.0.0`.

### 4.2. `quantization.block.v1` (`TEMPLATE-002`)
Splits tensors along key dimensions into blocks, computing independent scale/zero-points.
- **Parameters**:
  - `block_size`: `integer` in `[16, 32, 64, 128]`
  - `quantization_bits`: `integer` in `[4, 8]`
  - `symmetric`: `boolean`
- **Semantic Rule**: `block_size` must divide the inner dimension of the target workloads.

### 4.3. `sparsity.threshold.v1` (`TEMPLATE-003`)
Forces element-wise zeroing of values below absolute threshold limits.
- **Parameters**:
  - `threshold`: `number` in `[0.0, 1.0]`
  - `relative`: `boolean`
- **Semantic Rule**: If `relative=true`, threshold represents variance ratio (`[0.0, 0.5]`).

### 4.4. `decomposition.svd.v1` (`TEMPLATE-004`)
Compresses representation using Singular Value Decomposition truncation.
- **Parameters**:
  - `target_rank`: `integer` in `[1, 128]`
- **Semantic Rule**: `target_rank` must be less than the minimum dimension of the workload tensor.

## 6. Compiler Pipeline Phases & Contracts

Compilation runs as a strict, fail-fast sequence. No later compiler stage SHALL execute after an earlier stage has failed. Stage inputs are immutable frozen objects.

Every pipeline phase implements the following protocol:
```python
class CompilerStage(Protocol):
    def execute(self, input: T) -> U: ...
```

```
       Raw IR Input JSON String (Untrusted)
                 │
                 ▼
          [Stage 1: ParserStage]            ──►  Outputs ParsedIR (Frozen Dataclass)
                 │
                 ▼
      [Stage 2: SchemaStage]                ──►  Outputs ValidatedIR (Frozen Dataclass)
                 │
                 ▼
        [Stage 3: CanonicalizerStage]       ──►  Outputs CanonicalIR (Frozen Dataclass)
                 │
                 ▼
     [Stage 4: SemanticStage]               ──►  Outputs SemanticIR (Frozen Dataclass)
                 │
                 ▼
      [Stage 5: TemplateStage]              ──►  Outputs GeneratedPlugin (Frozen Dataclass)
                 │
                 ▼
      [Stage 6: ASTStage]                   ──►  Outputs VerifiedPlugin (Frozen Dataclass)
                 │
                 ▼
          [Orchestrator]                    ──►  Assembles public CompilerArtifact
```

### 6.1. Stage 1: ParserStage
- **Input**: Raw UTF-8 JSON string.
- **Output**: `ParsedIR` (frozen dataclass).
- **Failure**: Syntax/decoding errors abort immediately with error `IR:PAR_001`. No mutation.

### 6.2. Stage 2: SchemaStage
- **Input**: `ParsedIR` object.
- **Output**: `ValidatedIR` (frozen dataclass).
- **Failure**: Structural deviations or invalid types abort with `IR:SCH_002`. No mutation.

### 6.3. Stage 3: CanonicalizerStage
- **Input**: `ValidatedIR` object.
- **Output**: `CanonicalIR` (frozen dataclass containing canonical JSON UTF-8 byte string complying with RFC 8785).
- **Failure**: Normalization formatting failures abort with `IR:CAN_003`.

### 6.4. Stage 4: SemanticStage
- **Input**: `CanonicalIR` object.
- **Output**: `SemanticIR` (frozen dataclass mapping verified strategy values to hardware targets).
- **Failure**: Divisor bounds or constraint limits violations abort with `IR:SEM_004`. No mutation.

### 6.5. Stage 5: TemplateStage
- **Input**: `SemanticIR` object combined with compile-time `CompilationPlan`.
- **Output**: `GeneratedPlugin` (frozen dataclass containing the populated Python code string).
- **Failure**: Variable replacement or strategy mapping errors abort with `IR:TMP_005`.

### 6.6. Stage 6: ASTStage
- **Input**: `GeneratedPlugin` object.
- **Output**: `VerifiedPlugin` (frozen dataclass confirming compiler AST sanity).
- **Failure**: Import violations or illegal python constructs abort with `IR:AST_006`.

## 7. Build Hash Dependency Graph

The compiler structures generated file integrity hashes as a deterministic dependency graph. Hashes are derived artifacts and SHALL NEVER be treated as compiler inputs:

```
          Raw IR Input
                │
                ▼
         [Stage 1: Parser]
                │
                ▼
     [Stage 2: Schema Validator]
                │
                ▼
       [Stage 3: Canonicalizer] ──► ir_hash = SHA256(canonical_ir)
                │
                ├──────────────────────┐
                ▼                      ▼
     [Stage 4: Semantic Val.]   [Stage 4: Semantic Val.]
                │                      │
                ▼                      ▼
     [Stage 5: Template Gener.] ──► generated plugin.py ──► plugin_hash = SHA256(plugin.py)
                │                                                │
                └──────────────────┬─────────────────────────────┘
                                   ▼
                            manifest.json ──► manifest_hash = SHA256(manifest.json)
```

## 8. Compiler Manifest Schema

For every compiled plugin, the compiler writes a companion `manifest.json`:

```json
{
  "manifest_version": "1.0.0",
  "compiler_pipeline": "IRCompiler-v1",
  "compiler_abi": 1,
  "compiler_version": "1.0.0",
  "ir_version": "1.0.0",
  "ir_abi": 1,
  "ir_hash": "2f718aa0...",
  "template_id": "TEMPLATE-001",
  "template_version": "1.0.0",
  "template_abi": 1,
  "template_hash": "a8f6e2b1...",
  "registry_version": 1,
  "registry_hash": "9b1a2c3d...",
  "plugin_hash": "9c1b3c8f...",
  "manifest_hash": "e3b0c442...",
  "generated_at": "2026-07-03T00:52:00Z",
  "generator": "IRCompiler",
  "deterministic": true,
  "canonicalization": "RFC8785",
  "ast_guard_version": "1"
}
```

### Versioning Properties
- **`manifest_version`**: Tracks the schema structure of the manifest file itself.
- **`compiler_version`**: Tracks the software release implementation of the compiler.
- **`compiler_abi`**: Tracks structural build compatibility of emitted artifacts.
- **`generated_at`**: ISO 8601 UTC timestamp. This field is **informational only** and SHALL NOT participate in any deterministic artifact comparison, replay verification, compiler hashes, golden-file verification, or ABI compatibility decisions.

---

## 9. Version & ABI Compatibility Rules

- **IR Version Compatibility**: Compiler ABI `1` accepts IR `1.0.x` and rejects IR `2.x`. IR ABI mismatch always fails at the Parser/Schema phase before semantic validation.
- **Strategy Registry**: The `StrategyRegistry` mapping strategy keys to template details is immutable at runtime, and is loaded once during module initialization. Runtime or dynamic template registration is prohibited.

---

## 10. Compiler Error Codes

Error codes are defined as a stable API and will never be recycled.

| Code (Internal) | Code (External) | Phase | Description |
|---|---|---|---|
| `PAR_001` | `IR:PAR_001` | Parser | Malformed JSON syntax |
| `SCH_002` | `IR:SCH_002` | Schema | Unrecognized schema version or structural mismatch |
| `CAN_003` | `IR:CAN_003` | Canonicalizer | Canonicalization normalization failure |
| `SEM_004` | `IR:SEM_004` | Semantic | Parameter out of bounds or strategy conflict |
| `TMP_005` | `IR:TMP_005` | Template | Template replacement error |
| `AST_006` | `IR:AST_006` | AST Guard | Generated Python code fails AST checks |
