# CRP Engineering Constitution

This constitution defines the immutable engineering principles governing the Cognitive Runtime Platform (CRP) and its research subsystem. All modifications, optimization policies, and architectural evolutions must comply with these rules.

---

## The Eight Principles

### 1. Runtime Non-Self-Modification
The execution runtime never modifies its own code or repository directly. Software evolution occurs exclusively through generating recommendations, creating isolated bundles, and obtaining human verification.

### 2. Mandatory Replay Validation
All performance claims, execution optimizations, and representation gains must be validated through exact workload replay before they are considered for promotion.

### 3. Evidence is the primary basis for engineering decisions
Decisions regarding representation selection, constraint thresholds, and scheduling policies must be backed by empirical telemetry recorded in the Experience Database. While intuition generates hypotheses, candidate code does not become runtime behavior without verified empirical evidence.

### 4. Preservation of Failures
The Research Ledger must document all failed experiments, syntax errors, and constraint rejections. Historical failure records are preserved permanently as scientific evidence to guide future search strategies.

### 5. Mandatory Reproducibility
Every experiment must be fully reproducible. If an Experiment Bundle cannot be replayed to produce equivalent outcomes within versioned baselines, the experiment is invalid.

### 6. Human Review & Promotion
Humans govern the codebase. The Research Engine acts as an advisor producing recommendation bundles; promotion of code into the active CRP registry must be committed manually through the standard Git/PR review workflow.

### 7. Stability Over Experimental Gain
Runtime stability and predictability are always preferred over experimental performance gains. If a candidate optimization carries any risk of OOM, segmentation fault, or accuracy degradation past safety thresholds, the runtime must fall back to the safe `Dense` representation.

### 8. Template Determinism
For any `(canonical IR, compiler ABI, template version)`, the generated `plugin.py` and `manifest.json` SHALL be byte-identical across all supported platforms, environments, locales, timezones, and executions. Any change that alters generated bytes constitutes a compiler compatibility event requiring an ABI review or a new compiler version.
