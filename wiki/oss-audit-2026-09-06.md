# OSS Audit — 2026-09-06 (17 repos)

> Synthesized evaluation of a 17-repo open-source roundup, judged for leverage against
> this workspace's existing stack (graphify, memory_os, `.remember/`, the 168-skill mesh,
> Obsidian vault). Second audit of this kind — the first covered 12 repos in the week of
> 2026-08-11 (recorded in `.remember/archive.md`; no wiki page was written for it).

## Evidence boundary

This page was written in **two passes with different evidence strength**. Read the boundary
before citing anything from it.

**Pass 1 — survey (everything above "Deep research pass").**
Derived from **GitHub REST API metadata + README text only**, retrieved 2026-09-06.
No repository was cloned; no source file was read. Claims about **license, activity,
maintainership, platform, and stated scope** are evidence-backed. **No code-quality claim is
made** and none may be inferred.
Method: `GET /repos/{owner}/{repo}`, `/contributors`, `/license`, and
`raw.githubusercontent.com/{repo}/{branch}/README.md`. The unauthenticated rate limit (60/hr)
was exhausted partway; READMEs were pulled from `raw.` to work around it.

**Pass 2 — deep research (the "Deep research pass" section).**
Adds authenticated issue-tracker reads (`gh api`, 5,000/hr), a **full clone and complete source
read of `EfficientStreet/hindsight`**, targeted source and config reads of `every-app/open-seo`,
`Kayforkind/reimagine-it`, and `K-Dense-AI/scientific-agent-skills` via `raw.`, and **two checks
run against this machine directly**. Findings in that section state their own evidence inline.

**Still not done for any repo other than hindsight:** a full source read. archify, open-seo,
rta-smriti-brain, and reimagine-it were assessed from issue trackers, READMEs, and selected
files — not audited.

### The cortex_suite lesson

Its premise is the strongest idea in the whole list: an **enforced** split between
*structure* (what the code is — parsed live from source, no hand-written knowledge) and
*judgment* (what you learned — patterns, decisions, corrections), with both fed by one
extractor so they cannot disagree. It also tags confidence three ways
(`resolved` then `name_resolved` then `ast_only`) rather than as a boolean, on the stated
grounds that *an agent cannot calibrate what it is told if everything arrives with the same
authority*.

That principle belongs in graphify. The code cannot be used.
**Take the architecture, leave the repo.**

### hindsight — the one adoption

A single `SKILL.md`. No dependencies, no API keys, no service, no runtime.
Its claim: *filter what is worth remembering, rather than journal what happened* —
root causes over symptoms, updates existing memory entries in place instead of duplicating,
and reports "nothing to report" on a clean session rather than padding.

**Why it fits here:** the current `.remember/` handoff has been re-delivered 20 times since
2026-08-26 with no new handoff written. That is a system that **captures state but does not
distil lessons.** Hindsight is exactly the missing distillation pass, and it sits alongside
the existing memory layer rather than replacing it.

**Risk accepted:** 1 contributor, 3 weeks old, 58 stars. Because it is a prompt file with zero
runtime, **abandonment risk is nil** — a local copy keeps working if the author disappears.
That asymmetry (real upside, no operational dependency) is what makes it the highest
expected-value item on the list.

**Pre-install requirement:** a third-party `SKILL.md` dropped into a trusted skills root is a
prompt-injection surface. Read it in full before installing, then install to the canonical root
(`~/.claude/skills/hindsight/`) with junctions everywhere else, per the standing
one-canonical-copy rule.

### rta-smriti-brain — take the model, not the daemon

Unusually rigorous README: bitemporal truth, explicit output budgets, a verification ledger,
and — the important part — **captured evidence is treated as untrusted until an operator or
verifier promotes a claim.**

That property is a direct structural answer to this workspace's own recorded failure modes:
the Signal-app fabrication, the Interactor offline-fallback masking real failures, and the
subagent that self-reported completion without doing the work.

Against it: `v1.0.4-alpha`, 2 contributors, and heavy overlap with `memory_os/` and graphify.
Its README also states it was built primarily by OpenAI Codex under human direction — neutral
in itself, but it implies the agentic-bloat profile that Karpathy Principle 6 warns about.

**Verdict: port the bitemporal and evidence-promotion model into `memory_os/`.
Do not install a second memory daemon** — that would violate the one-canonical-copy rule
at the system level, not just the file level.

### reimagine-it — cheap to test

`npx reimagine-it --auto -i page.html -o redesign.html`. HTML in, standalone redesigned HTML
out, source untouched. Strong repo hygiene signals (SHA-pinned actions, OpenSSF Scorecard,
secret-scanning push protection, SLSA provenance, protected main plus CODEOWNERS).
Zero install commitment, so the trial *is* the evaluation.

## Standing caveats

**Star counts were not used as a quality proxy, and should not be.**
`tt-a1i/archify` reached 49,583 stars in under five months (created 2026-04-15).
`Gitlawb/openclaude` shows 9,063 forks against 32,723 stars — a 1:3.6 fork-to-star ratio,
where healthy libraries typically sit near 1:8 to 1:15. A high fork ratio indicates cloning to
run, not depending on. No accusation is made; the metric simply carries no weight in the
verdicts above.

**Overlap with existing infrastructure is a cost, not a feature.**
Every tier-2 memory tool duplicates something already built here. Running two systems that
answer the same question creates two sources of truth — which the standing
*"one canonical copy — link, never copy"* rule forbids. This is why exactly **one** adoption
is recommended rather than three.

**Rust toolchain constraint.** cortex_suite is Rust plus tree-sitter. Even absent the licensing
block, the documented broken MSVC toolchain here (GNU plus WinLibs `dlltool` workaround) is the
real barrier to any tree-sitter-based multi-language extractor on this machine.

# Deep research pass

Second pass, 2026-09-06. Issue trackers read under authentication, `hindsight` cloned and read
in full, selected source and config files read for four other repos, and two checks run against
this machine. Findings below carry their evidence inline.

## The most underrated item: an agent-skill security scanner

`K-Dense-AI/scientific-agent-skills` ships **`scan_skills.py`** — an LLM-backed **security
scanner for agent skills**. It runs in CI, scans skills concurrently, caches results by content
hash (invalidated by scanner version, model change, `--full`, or age), and emits severity-ranked
findings as paired Markdown + JSON reports.

It is built on **`cisco-ai-skill-scanner>=2.0.12`** (`pyproject.toml`), a pip-installable
package exposing `SkillScanner`, `Severity`, `Finding`, and `ScanResult`.

**Why this matters more here than anything else on the list:** this workspace maintains
**168 skills full-mesh-junctioned into four trusted roots** with an auto-sync watcher running
as a Windows startup task. There is no scanning step anywhere in that pipeline. A malicious or
compromised skill file propagates to all four roots automatically, and skills are executed with
the agent's own trust.

The science skills themselves are irrelevant here. **The scanner and the packaging are the
takeaway.**

## Ecosystem tooling already installed and unused

Verified on this machine: **`gh` 2.95.0**, and `gh skill` exists in preview with
`install`, `list`, `preview`, `publish`, `search`, `update`.

Two standards are now in play, and archify, reimagine-it, and scientific-agent-skills all
publish through them:

- **Agent Skills** (`agentskills.io`) — installable via `npx skills add <owner>/<repo>`,
  supporting Claude Code, Codex, Gemini CLI, Antigravity, and Cursor.
- **Agent Plugins** (`agent-plugins.org`) — `plugin.json` + `skills/` loads a whole collection
  as one plugin.

**This does not replace the junction model.** `gh skill install` does not enforce the
one-canonical-copy rule; the junction mesh does. But **`gh skill preview` is strictly better
than `git clone` for inspecting a third-party skill before trusting it**, and should become the
default first step for any future skill adoption.

## archify — five open Windows defects, and two that are worse

| Issue | Applies here? |
|---|---|
| #310 libuv native assertion crash on 8.3 short-name paths | **No — verified below** |
| #274 `--repo-root` rejected when the Windows drive letter is lowercase | **Live risk** |
| #276 `--repo-root` filesystem path semantics on Windows | Open |
| #318 Git isolation not portable on Windows | Open |
| #320 preview graceful shutdown untested on Windows | Open |

**#310 checked directly against this machine and ruled out.** The bug triggers when the user
profile directory has an 8.3 short-name alias — generated when the name exceeds 8 characters or
contains a space (`C:\Users\JULIAN~1\...`). Here the profile is `navka` (5 chars):
`cmd /c dir /x C:\Users` returns an **empty short-name column** for it, and `$env:TEMP` resolves
to the long form `C:\Users\navka\AppData\Local\Temp`. The alias does not exist, so
`fs.mkdtempSync(os.tmpdir())` cannot produce the short/long mismatch the assertion trips on.
Node here is v24.13.1; the bug was reported on v24.19.0, same major.

Two non-platform defects matter more than the Windows cluster:

- **#311** — `artifact-check` receipts larger than 64 KB are **truncated by `process.exit()`
  firing before `console.log`'s async stdout flush completes**, so `validate`, `deliver`, and
  `compare` all die with `SyntaxError: ... JSON at position 65536`. A plain 20-component
  architecture map already produces a 96,432-byte receipt. This is the classic Node
  exit-before-flush bug and it sits on the primary code path.
- **#324** — **three of five packaged examples fail archify's own visual-check containment
  gate** at every desktop viewport, while `SKILL.md` instructs the agent to read an example
  *before* authoring. An agent inherits a layout that cannot pass, and discovers it only after a
  full authoring loop. The reporter also found that `validate` can pass 9/9 with zero errors
  while the delivered artifact still fails containment.

Label hygiene is poor: 118 open issues, exactly **one** labelled `bug`, so the label count
badly understates the real defect load.

**Verdict unchanged, now evidence-backed: do not migrate graphify to archify.**

## open-seo — fails the "free or almost free" filter

`DATAFORSEO_API_KEY` is a **hard dependency**, marked *"Required for SEO data features"* in
`.env.example`. The README's "No subscriptions" bullet sits three lines above "you need a
DataForSEO API key". Hosted is $10/mo; self-hosted you pay DataForSEO directly (hosted adds a
28% markup, so self-hosting is cheaper — but not free).

**Spend is invisible in self-hosted mode.** Per issue #268: `meterDataforseoCall` in
`src/server/lib/dataforseo/client.ts` returns early when not hosted, **discarding
`result.billing.costUsd`** even though every DataForSEO response carries it; `/billing` calls
`notFound()` outside hosted mode. The reporter's summary: scheduled rank checks and site audits
*"quietly burn through a DataForSEO balance, and the first sign is a failed run."*

**The free-tier path does not exist yet.** Issue #294 proposes DataForSEO-free degradation
(Google Trends, Bing Webmaster fallbacks, PageSpeed Insights). Checked: it is an **open issue,
never merged**, and both `src/server/lib/google/trends.ts` and `src/server/lib/bing/client.ts`
return **404 on `main`**.

Open correctness bugs worth knowing: #293 (meta description reported missing when present),
#289 (a clean audit reports "no issue data" instead of "no issues"), #273 (**CJK/Indic word
counting uses a whitespace split** instead of `Intl.Segmenter`), #291 (Backlinks Overview fails
for subdomains), #272 (crawl burst 429'd by Shopify storefronts).

**Revised verdict: do not deploy the app.** The existing `openseo-content-optimizer` skill is
the free half — methodology, no paid API. Keep it; the diff is informational only.

## hindsight — full source read, clean

All 8,779 bytes of `SKILL.md` plus `GUIDE.md` read after a full clone.

```
allowed-tools: Read, Write, Edit, Glob, Grep
disable-model-invocation: true
```

No Bash, no network. A grep for `network|http|curl|fetch|api key|token|exec|bash` matched only
the author's YouTube and website links in `GUIDE.md` prose. `disable-model-invocation: true`
means it **cannot self-trigger** — it fires only on explicit user request, which is the correct
default for anything that writes persistent memory.

Two properties not visible from the README:

**It already targets this exact memory layout.** The skill names
`~/.claude/projects/<project-slug>/memory/`, one markdown file per fact, `name`/`description`/
`metadata.type` frontmatter, `type: feedback` as the default for process lessons, and
`MEMORY.md` as the index requiring an entry per new file. Zero adaptation needed.

**Its Step 4 is a stronger evidence rule than the one in [gbrain](../CLAUDE.md).** It separates
*proved* (the same failure occurred more than once, the root cause was confirmed against real
tool output or file contents, or a fix was verified) from *suggested* (happened once, plausible,
unconfirmed). A merely-suggested lesson is either held out of memory as a named watch-item, or
persisted **with the uncertainty stated inside the entry** — never written as an unqualified
rule from a single occurrence.

gbrain's Evidence Rule gates *"does it work."* This gates *"is one observation a pattern."*
That is the failure mode behind the Signal-app fabrication and the subagent self-report
incident. **Port it into gbrain regardless of whether the skill is installed.**

## Corrections and additions to Pass 1

- **reimagine-it ships an MCP server** — `package.json` declares a `reimagine-it-mcp` bin and
  an optional `@modelcontextprotocol/sdk` dependency. Pass 1 described it as a CLI only; it is
  MCP-connectable, which is materially more interesting given the MCP servers already running here.
- **reimagine-it is untested on Windows.** CI is `ubuntu-latest` only across every job;
  `engines` is `node>=18` with no `os` restriction, so it should run. Treat the trial as the
  Windows test, not a formality.
- **rta-smriti-brain's benchmark documentation is unusually honest** and raises the read on its
  engineering culture. `docs/PUBLIC_BENCHMARK.md` states outright that perfect scores are
  *"reproducibility evidence for these fixtures, not external proof of agent success or
  superiority over another memory system,"* and emits `optional_semantic: status: not_requested`
  so omitted optional evidence cannot be mistaken for a completed comparison. It also measures
  **required-control density per 1,000 estimated input tokens at a fixed effective budget** — a
  context-efficiency metric worth stealing for `memory_os/`. The overlap argument against
  installing a second memory daemon still stands.
- **rta-smriti-brain has no external bug reports.** Every issue is self-authored release
  chore-work, mostly opened and closed the same day — consistent with the 2-contributor count.
- **hindsight has zero issues of any kind**, consistent with 1 contributor and a prose-only repo.
