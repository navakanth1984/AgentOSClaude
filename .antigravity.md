## graphify

This project uses graphify knowledge graphs under `.graphify/` per repo or app. `graphify-out/` is legacy state only; prefer `.graphify/` and migrate only with an explicit plan.

Rules:
- For codebase or architecture questions, start from `wiki/knowledge-base-map.md`, then query the relevant `.graphify/graph.json` or read that repo's `.graphify/GRAPH_REPORT.md` for broad orientation.
- If `.graphify/wiki/index.md` exists, navigate it instead of reading raw files.
- For cross-module "how does X relate to Y" questions, prefer `graphify query "<question>"`, `graphify path "<A>" "<B>"`, or `graphify explain "<concept>"` over grep — these traverse the graph's EXTRACTED + INFERRED edges instead of scanning files
- After modifying code, run `graphify update <repo-path>` to keep the relevant graph current (AST-only, no API cost).

## Usage Limit & Context Optimization Protocol (ULCOP v2.1)

### ULCOP Decision Order
To prevent optimization from leading to incomplete or incorrect implementations, all operations must be evaluated using this priority stack:
1. **Safety**: Ensure operations do not violate safety boundaries, create security vulnerabilities, or risk data loss.
2. **Correctness**: Maintain absolute code correctness, logic fidelity, and alignment with specifications.
3. **Task Completion**: Achieve all objectives fully, avoiding half-baked edits or skipping necessary details.
4. **Context Efficiency**: Keep the context window compact using smart truncation, graph-first lookups, and timely subagent delegation.
5. **Response Brevity**: Keep chat responses clean and focused, adjusting depth to match task complexity.

*If a higher-priority objective conflicts with a lower-priority objective, the higher-priority objective wins.*

### Core Operational Principles
- **Decision Hierarchy Override**: Apply ULCOP principles by default, unless doing so would reduce safety, correctness, or task completion quality.
- **Graph-First Search Preference**: Prefer graph-based discovery (`graphify`) and targeted searches when available. Use broader search techniques when required for correctness or completeness.
- **Reasoning Cost Management**: 
  1. **Complete Over Partial Investigations**: Prefer one thorough, high-fidelity investigation over multiple partial investigations.
  2. **No Redundant Planning**: Avoid repeated planning loops; formulate and execute a clean plan.
  3. **Evidence Reuse**: Reuse previously gathered evidence, logs, and files; do not re-read unmodified files.
  4. **Consolidated Edits**: Consolidate related code edits into a single multi-replace block.
  5. **No Redundant Subagents**: Avoid spawning duplicate subagents; consolidate tasks when executing background operations.
  6. **Targeted Verification**: Prefer targeted verification over running full-system tests unnecessarily.
- **Heuristic Delegation**: Prefer delegation when it improves context efficiency without reducing correctness or completeness, and when the expected investigation cost materially exceeds the cost of delegation and isolation.
- **Contextual Response**: Match explanation depth to task complexity and user expectations.

## 🗂️ Sub-Agent & Workspace Management Guidance

> **Full 9-stage lifecycle** (pre-flight → work tree → develop → verify → PR → staging → production → graduation → KB handoff) is codified in **[wiki/agentic-dev-lifecycle.md](wiki/agentic-dev-lifecycle.md)**. All agents must follow it end-to-end every session.

Whenever delegating to a sub-agent, creating a Git work tree, or performing any workspace isolation:

1. **Highlight Actions:** Explicitly tell the user when a Git work tree is being created, used, or cleaned up — e.g., *"Creating an isolated Git work tree for this sub-agent…"*
2. **Feature Reminders:** Proactively remind the user of available workspace features where appropriate:
   - **Desktop App → New Conversation:** Select **"New Work Tree"** to auto-configure an isolated environment before the agent starts.
   - **Sidebar Toggle:** Work tree names can be toggled on/off in the sidebar — useful when running multiple agents across projects.
   - **Conversation Grouping:** Group conversations by project, status, or recency via the sidebar.
   - **Background Scheduling:** Tasks can be scheduled to run automatically in the background from the desktop app.
3. **Work Tree Integration (MANDATORY):** After a sub-agent work tree is closed, the agent MUST:
   - Push the branch to `origin`
   - Immediately open a PR into `master`: `gh pr create --base master`
   - Announce: *"Work tree cleaned up. PR #N is open — awaiting your review."*
   - **Never leave a branch dangling without a PR. The task is NOT done until the PR is open.**
4. **Staging → Production Pipeline:** After merge, follow the deployment stages:
   - **Stage 5:** Deploy to staging environment and announce the staging URL.
   - **Stage 6:** Run automated smoke tests + report pass/fail per check.
   - **Stage 7 — Production + 15-min monitoring window:**
     - Deploy only after explicit user approval.
     - Confirm live via health check / status endpoint.
     - Run `curl` smoke test against the **production** URL (not staging).
     - For web apps: take a live screenshot via `chrome-devtools-mcp` and confirm no console errors.
     - Monitor for 15 minutes — alert user immediately on any anomaly.
     - **If prod deploy fails: rollback first, investigate second. Never debug on live traffic.**
5. **Stage 8 — Project Graduation Gate:** After a successful production deploy, check:
   - Does this project have its own domain in production?
   - Does it have its own CI/CD pipeline?
   - Does it have 3+ external users?
   - Are its PRs polluting unrelated changes in this repo?
   - If **2 or more** are true → propose graduation using `graduate-project.ps1` and update `wiki/knowledge-base-map.md`.
6. **Automatic Cleanup:** Work trees are deleted automatically after tasks complete — no manual action needed.
7. **KB Handoff + Context Rot (every session end):**
   - **Context rot threshold:** If token usage approaches **~250K tokens**, write a handoff and start a fresh session — do not push through it. Signs: agent forgets earlier constraints, revisits locked decisions, produces lower-quality output.
   - Update `wiki/log.md`, the relevant wiki page, `memory_os/session_memory/`, `.remember/remember.md`, and `memory_os/long_term_knowledge/lessons_learned.md` (for any new patterns discovered).
   - Run `py -3 memory_os/scripts/validate_usage_efficiency.py` and `py -3 agent_os/session_end.py`.

> This directive is loaded from `.antigravity.md` and applies to every `agy` CLI and Antigravity desktop session in this workspace.

## ✅ Session End Routine (Mandatory — every session, planned or abrupt)

Execute this checklist at the end of **every** session — whether planned shutdown or abrupt disconnect:

### Step 1 — Lifecycle Sync Check
- Compare `wiki/agentic-dev-lifecycle.md` with `.antigravity.md`.
- If any new rules were added to the lifecycle doc this session → mirror actionable items into `.antigravity.md`.
- Takes ~60 seconds. Never skip.

### Step 2 — Context & Branch State
- List open branches: `git branch -a | grep -v master`
- If any branch has no PR: `gh pr create --base master --draft` before closing.
- If token usage ≥ 250K: write handoff now, not next session.

### Step 3 — KB Close-Out
1. `wiki/log.md` — dated summary (actions, merged PRs, open WIP)
2. Relevant `wiki/<topic>.md` — update with new state
3. `memory_os/long_term_knowledge/lessons_learned.md` — new patterns, bugs, mismatches
4. `.remember/remember.md` — refresh cold-start buffer

### Step 4 — Session Scripts
```powershell
py -3 memory_os/scripts/validate_usage_efficiency.py
py -3 agent_os/session_end.py
```

### Step 5 — Handoff File (write always, even on clean shutdown)
Write to `memory_os/session_memory/session_<YYYYMMDD>.md`:
```
## Current Status     — Done / In-flight (branch + PR # if applicable)
## Key Files          — [path] — [purpose]
## Locked Decisions   — [decision] — [why locked]
## Next Steps P0/P1/P2
## Abrupt Disconnect Flag: Yes / No
```

## 🔌 Abrupt Disconnect / Cold-Start Reconnect Protocol

When a session was cut off (network drop, crash, token limit, user closed session), the **next agent to open this workspace** must run this automatically — no user prompt needed:

1. **Read `.remember/remember.md`** — fastest cold-start signal.
2. **Read latest `memory_os/session_memory/session_<YYYYMMDD>.md`** — find most recent handoff.
3. **Check dangling branches:** `git branch -a | grep -v master` → open PRs for any without one.
4. **Check open PRs:** `gh pr list --state open` → surface to user.
5. **Read last 10 lines of `wiki/log.md`** → confirms what was last completed.
6. **Run Lifecycle Sync Check** → confirm `.antigravity.md` is up to date.
7. **Announce:** *"Reconnected after disconnect. Last session: [summary]. Open PRs: [N]. Dangling branches: [N]. Ready to resume from: [P0 next step]."*

> Trigger condition: prior handoff file exists from same calendar day **OR** `Abrupt Disconnect Flag: Yes` in latest session memory.
