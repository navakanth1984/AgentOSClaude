## 🎯 Mode: Product Execution (Status: ACTIVE)

Governance and architecture documents are **frozen**. Do not spend cycles expanding governance unless a production blocker or cross-project architectural discovery requires it. The primary objective is shipping a production-grade product.

### North Star & Definition of Done (DoD)
Build **Interactor** into a production-quality interactive experience platform with advanced frontend interaction capabilities.
A task or milestone is considered **Done** only when:
*   ✓ **Green CI**: All pipeline checks, types, and build scripts pass successfully.
*   ✓ **E2E Validation**: All Playwright E2E tests are 100% green on Chromium/Firefox/Webkit.
*   ✓ **Accessibility Compliance**: Passes core AX rules (contrast, aria-labels, role mapping).
*   ✓ **Performance Limits**: Satisfies target response, interaction, and rendering speeds.
*   ✓ **Zero Open P0/P1 Defects**: No unresolved blockages or visual/behavioral regressions.
*   ✓ **Staged/Deployed**: Successfully built and deployed to the production staging workspace.

### Core Optimization Equation
$$Engineering\ ROI = \frac{User\ Value \times Knowledge\ Reuse}{Token\ Cost \times Execution\ Time}$$
*   **User Value**: Impact on Creator/Explorer journeys.
*   **Knowledge Reuse**: Existing ADRs / OCOS / Graph usage.
*   **Token Cost**: Prompt + response + rereads.
*   **Execution Time**: Wall-clock duration.

## 📜 Invariant Gates, Budgets, & Stop Rules

### Principle 1: Never reload knowledge that already has an authority
Instead of reloading multiple raw documents, reference their canonical owners. Only load details when editing that authority.

### Principle 2: Read minimum viable context
Before opening files, ask: *Can this be solved from the graph?* If yes, don't grep or recursively scan.

### Principle 3: Context Budget
Every task starts with:
*   **Target Context**: Bug fix (`5k–15k`), Small feature (`10k–25k`), Medium feature (`20k–40k`), Architecture (`40k–80k`) tokens.
*   **Boundaries**: Soft Warning (`30k`), Hard Stop (`40k`). *Need human justification above 40k.*

### Principle 4: Progressive Loading
Traverse step-by-step: $\text{Index} \rightarrow \text{Graph} \rightarrow \text{Header} \rightarrow \text{Relevant section} \rightarrow \text{Exact lines} \rightarrow \text{Whole file (only if required)}$.

### Principle 5: One Authority Rule
Every concept has exactly one owner:
*   `ADR-010` (Evidence), `ADR-012` (Learning), `OCOS` (Governance), `operating_system.md` (Runtime), `status.md` (State), `.remember/remember.md` (Memory).

### Invariant: Product First Gate
Before initiating any governance or planning work, Antigravity MUST confirm that at least one of these is true (otherwise postpone the work):
1. Does this ship a user-visible improvement?
2. Does it unblock shipping?
3. Does it reduce future engineering cost?

### Invariant: Stop Rule
If the proposed work does not improve the product, reduce engineering cost, or discover a new reusable architectural primitive, stop and delegate implementation to Claude Code or Codex.

### Sprint Allocations
Exceeding these target allocations requires explicit human justification:
*   **Product Implementation (React, backend, UX)**: $\ge 80\%$
*   **Testing, Validation, Accessibility, Performance**: $\approx 10\%$
*   **Architecture & Planning**: $\le 5\%$
*   **Governance & Documentation Maintenance**: $\le 5\%$

## 🔍 Graphify as a Context Optimizer
The graph is a context-reduction tool. Before loading files, Antigravity MUST:
1. Query graph to identify target files and affected modules.
2. Load only the minimum context slice needed (affected files and direct headers/dependencies).
3. Execute the planning or routing work.
4. Update the graph (`graphify update`) only if files or structure changed.

## 🔌 Abrupt Disconnect / Cold-Start Reconnect Protocol

When a session was cut off (network drop, crash, token limit, user closed session), the **next agent to open this workspace** must run this automatically — no user prompt needed:

1. **Read `.remember/remember.md`** — fastest cold-start signal.
2. **Read latest `memory_os/session_memory/session_<YYYYMMDD>.md`** — find most recent handoff.
3. **Check dangling branches:** `git branch -a | grep -v master` → open PRs for any without one.
4. **Check open PRs:** `gh pr list --state open` → surface to user.
5. **Read last 10 lines of `wiki/log.md`** → confirms what was last completed.
6. **Run Lifecycle Sync Check** → confirm `.antigravity.md` is up to date.
7. **Announce:** *"Reconnected after disconnect. Last session: [summary]. Open PRs: [N]. Dangling branches: [N]. Ready to resume from: [P0 next step]."*

> Trigger condition: prior handoff file exists from same calendar day **OR** `Abrupt Disconnect Flag: Yes` in latest session memory.
